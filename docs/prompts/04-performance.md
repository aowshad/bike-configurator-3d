# Prompt: make the configurator lightweight and smooth

Paste everything below the line into Claude Code, opened in the `bike-configurator-3d` repo.

---

Read `CLAUDE.md` and `docs/ARCHITECTURE.md` first and follow their rules.

The configurator feels heavy and laggy, especially full-screen on a retina laptop and on phones. Make it fast **without a visible quality drop when the bike is at rest**. Work in the phases below. Measure before and after each phase, and commit after each one.

## Phase 0: Measure first
- Add a `?perf` overlay (hidden by default) showing:
  - FPS and frame time (avg and worst over the last 2s)
  - from `renderer.info`: draw calls, triangles, shader programs, geometries, textures
  - JS heap, if the browser exposes it
- Write a baseline in `docs/PERF.md` with these 4 scenarios, the same camera views, and screenshots:
  1. 1440×900 at DPR 2, idle
  2. 1440×900 at DPR 2 while dragging
  3. 375×812 with 4× CPU throttle
  4. first load on "Fast 4G": time to first visual, time to interactive, MB transferred

## Phase 1: Stop wasting frames (biggest win)
- **Render on demand.** Right now the loop renders every frame even when nothing moves. Render only while something is changing: OrbitControls `change`/damping, camera tweens, material or deform animations, auto-rotate, or a text redraw. Use one `requestRender()` that schedules a single frame. When idle, the GPU should do nothing.
- **Pause when the stage isn't visible:** the tab is hidden, or (on mobile) the stage is scrolled away. Use `visibilitychange` and `IntersectionObserver`.
- **Adaptive resolution:**
  - Cap the pixel ratio at 1.5 on desktop and 1.25 on mobile.
  - While dragging or zooming, drop to 1.0. About 200ms after input stops, render one full-quality frame.
  - If frame time stays above 20ms, step the resolution down. If it stays under 10ms, step it back up.
- **Static shadows:** set `shadowMap.autoUpdate = false`, and set `needsUpdate` only when geometry or visibility changes (tire swap, deform, guide or pedals). A 1024 shadow map is enough.

## Phase 2: Lighter geometry and draw calls
- In `tools/model-pipeline/`, build **two LODs** from the same source:
  - `bike-lod0.glb`: the current detail, simplified further wherever it doesn't show. Spoke nipples (143k tris) can go to under 10k, and remove interior and hidden faces.
  - `bike-lod1.glb`: about 300k tris for phones, for dragging, and as the first quick load.
  - Targets: desktop at rest ≤ 700k tris, interaction and mobile ≤ 300k.
- **Progressive load:** show a pre-rendered poster image (`assets/poster.webp`, generated by a script) immediately. Load `lod1` first (aim for ≤ 2 MB) so the user can start configuring, then stream `lod0` in the background and swap it in without a pop. Keep every slot, material and decal mapping identical between the LODs (same node and material names). Add a check script that fails if they differ.
- **Merge static, non-configurable meshes** that share a material (hardware, black parts, bearings, cables) to cut draw calls. Keep configurable and pickable parts separate.
- **Raycasting:** pick against `lod1`, or add `three-mesh-bvh` and build the BVH in idle time. Never raycast 1.36M triangles on the main thread during pointer moves.

## Phase 3: Cheaper materials and shaders
- Use `MeshPhysicalMaterial` only where it shows: frame paint (clearcoat), chain and anodized (iridescence), saddle (sheen). Everything else becomes `MeshStandardMaterial`.
- Keep the no-recompile rule, and make sure the program count drops. Report it in PERF.md.
- **Generated textures:**
  - Use 256–512px, with anisotropy 4 instead of 8.
  - Share the decal canvases where the text and style are the same.
  - Dispose of anything replaced.
- **Look-card thumbnails:**
  - Render them lazily, only when the presets row is visible.
  - Render one per idle frame (`requestIdleCallback`), at 2× card size max, from `lod1`.
  - Cache them for the session.

## Phase 4: Low-end quality mode
- Auto-detect low-end devices from `navigator.deviceMemory`, `hardwareConcurrency`, a short frame-time probe, and `prefers-reduced-motion`. On those, use:
  - `lod1` only, no dynamic shadow (a baked soft contact-shadow texture under the bike instead), and DPR 1
  - standard materials, and no auto-rotate
- Add a small "Quality: Auto / High / Fast" option in the toolbar menu and save the choice in `localStorage`. It must look clean and fit the existing design.

## Phase 5: Loading polish
- Add `<link rel="preconnect">` for jsDelivr and `<link rel="preload" as="fetch" crossorigin>` for the first GLB.
- Use `three.module.min.js`.
- Don't block first paint on fonts.

## Rules
- **At rest, the bike must look the same as now.** Compare before/after screenshots from the same camera and put them in PERF.md. Quality may drop only while the user is dragging, and only in Fast mode.
- No new build step and no bundler. CDN modules are fine.
- Every existing feature must keep working: text spots, styles, deforms, look cards, share links, light/dark, and mobile.

## Done when
- Idle: 0 renders per second (confirmed with the overlay).
- Interaction at 1440×900 DPR 2: 55+ fps on an M1-class laptop. 375px with 4× throttle: 30+ fps.
- First visual (poster) under 1s, and configurable (`lod1`) under 3s on Fast 4G.
- `docs/PERF.md` has the before/after numbers and screenshots, `CLAUDE.md` gets the new performance rules, and everything is committed and pushed to `main`.
